# Collected checkout vouchers

- Checkout now loads voucher options through authenticated `POST /orders/preview`, without a manual-code entry. Options come from this user's AVAILABLE UserVoucher records, with server-computed savings, eligibility and rejection reason. Expired/otherwise ineligible remaining records are visible and disabled; spent records are excluded.
- Two independent categories: max one merchandise voucher and one shipping voucher. Initial preview requests `voucherCodes: [], autoSelectVouchers: true`; the server maximizes actual savings separately per category. Both minima/targets use original eligible merchandise value. Shipping is capped by the fee. Ties prefer earlier expiry then code.
- Manual selections, including none, switch to `autoSelectVouchers: false`. "Tự chọn giảm nhiều nhất" explicitly returns to automatic mode. Re-preview on cart-line/stock changes; never recalculate money on the client. Previous preview data is retained only within the same user while requests run; order/selection controls are locked during fetch.
- Submit `voucherCodes` from the accepted preview, with its expected amount/hash and existing idempotency key. API errors for invalid manual selections expose retry/automatic selection; an older backend lacking warehouse metadata fails closed.
- Picker lives in `CheckoutVoucherPicker.tsx`; category replacement in `services/checkout-vouchers.ts`; route and view updated. Separate summary lines retain merchandise/shipping discounts.
- Validation: full frontend suite, TypeScript and ESLint; .NET rules/commerce + isolated PostgreSQL dual-voucher and legacy shipping/refund flows. Browser synthetic fixture verified replace/clear/automatic restoration, actual discount summary, disabled options, and a 320px picker without overflow; no console errors. Fixture removed. No real user cart/order writes.
- Deployment dependency: deploy the backend contract together with frontend. No migration or dependency additions; no deployment/commit performed here.
