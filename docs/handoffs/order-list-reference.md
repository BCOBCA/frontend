# My orders reference cards

- `OrderListCard` matches the supplied card hierarchy: clickable order code + copy, placed time, colored status, shop link, product preview, total, state-specific actions. Native/web responsive layout, fallback image and missing-metadata handling.
- Per user clarification, display only the first order-item line for each shop, with a +N other products link. Quantities and line prices refer to that product; footer total remains the whole order total. Historic combined orders retain separate shop groups.
- `app/orders.tsx` retains login, error/empty states, paging/status/group filters. Query cache includes user ID. Copy uses Expo Clipboard with toast feedback. Cancellation uses the existing endpoint and refreshes list/detail, membership and vouchers. Shipping opens detail; review opens the single item's review or multi-item detail; single-product repurchase opens product selection. All statuses can open detail via order code.
- Backend `GET /orders` now adds optional `items` to summaries using a single batch query for the authorized page's order IDs. Existing item metadata includes image, variant, seller and active seller link. No migrations required; deploy backend alongside frontend. Older backends show the existing summary plus a prompt to view products in details.
- Validation: component/route tests cover preview/count, statuses, legacy shops, copy and cancellation; complete frontend suite passed before the extra route regression test, which also passed. TypeScript, uncached ESLint and Expo web export passed. Three backend store-split integration cases passed including list item ownership/mapping. Browser fixture verified desktop and 375px without overflow or hidden products appearing; no console errors.
