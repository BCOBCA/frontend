# Support attachments

- `/feedback` now picks one device file instead of asking for a URL. JPG/PNG/WebP preview; PDF/DOCX/XLSX/TXT show icon, extension and filename. Max 5 MiB; cancel preserves selection; replace/remove supported; success resets. Blob URLs are released on replacement/removal/unmount.
- `support-attachments.ts` uses SDK 58 `expo-document-picker`; `AttachmentField.tsx` renders previews. Upload happens only during submission. Upload URL is cached while retrying the same draft, then filename and URL are appended to existing feedback content. No schema change. Legacy `feedbackSchema.reference` stays compatible but is no longer editable in this form.
- Backend: authenticated, active-account POST `/api/feedbacks/attachments`, multipart `file`, existing image-upload rate limiter and request limits. `CloudinaryImageService.UploadAttachmentAsync` validates allowed extension/MIME/signatures, size, UTF-8 text and Office ZIP structure, rejecting macros. Image uploads reuse existing path; documents use Cloudinary raw uploads with generated IDs. Existing Cloudinary credentials required; provider settings can restrict document delivery.
- Tests: all 333 frontend tests pass, plus typecheck, web export and targeted uncached ESLint. Picker cancel/size/type/MIME/multipart and preview/action rendering covered; server tests added for PDF/TXT and invalid files. Full lint remains blocked by unrelated `OrderDetailView.tsx` parse error (line 94). Backend execution blocked: installed SDK 9.0.305 cannot target net10.0 (NETSDK1045).
- Browser verification uses synthetic session/API responses because local backend is unavailable: image loads, PDF name/type, replacement, cancellation, removal, multipart-before-feedback order and reset after success. No real feedback or provider upload performed.
- References: [Expo SDK 58 DocumentPicker](https://docs.expo.dev/versions/v58.0.0/sdk/document-picker/), [Cloudinary raw uploads](https://cloudinary.com/documentation/upload_parameters).
