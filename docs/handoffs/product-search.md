# Shared product search

- `/search` (SearchScreen) is the shared destination for root-category cards and the global header. Header submits on Enter or the clickable search icon; CatalogScreen no longer intercepts typing for local filtering. Category page remains category-only; home retains brand/product/service content.
- URL owns `search`, `categoryId`, `sort`, `page`; helpers in services/product-search.ts validate UUID/page/sort and trim/bound keywords to 200 characters. New search/filter changes reset page 1; pagination preserves other applied filters. Refresh/back/deep links restore the state.
- SearchScreen uses existing GET `/products` (20/page) and cached `/categories?pageSize=100`. Root category filtering includes active descendants in the current backend. Search results are products only, without banners/services. Existing ProductCard and its favorite invalidation work through the `products` query-key prefix.
- Page/Header gained optional onSubmitSearch. SearchScreen uses it to keep the applied category when submitting a new keyword; normal headers navigate with a fresh global search. Category/sort/reset and real loading/error/empty states are available on results.
- Verified: TypeScript, focused ESLint, 21 focused regression tests; live browser category click → search, keyword Enter retaining category, homepage search-icon navigation, URL reload, 320px layout without horizontal overflow, empty state and page 2/2. Public API returned four matching iPhone products under the root phone category. No backend/schema/data changes in this task.
- Dev preview used localhost:8081 because the online API's CORS blocks arbitrary local ports. No permanent env/CORS settings changed. One transient Expo navigation aria-hidden/focus warning appeared after category navigation; final page checks had no console errors.
