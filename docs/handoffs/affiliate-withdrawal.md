# Withdrawal request redesign

- `/withdrawal` renders WithdrawalScreen and a form scoped/remounted by user ID. Reference layout: available/withdrawable balance, amount field with effective limits, saved bank radio cards/add form, pink request summary immediately before red submit action.
- Summary uses server flat fee: gross amount, fee (`Miễn phí` only for configured zero), net. Currency supports two decimals. Pending commissions are excluded from withdrawable balance; debt disables withdrawal. Bank logos use neutral institution icons instead of invented assets.
- Queries: user-scoped `/affiliate`, `/affiliate/bank-accounts`; effective `/affiliate/withdrawal-settings`. New bank data posts to server, is not put in browser storage, and added bank is selected immediately. Account numbers displayed masked.
- POST sends gross amount, selected bank ID and reviewed configuration revision with stable Idempotency-Key. Synchronous locks prevent double clicks. On ambiguous network/5xx failure, edits lock and retry reuses exactly the same payload/key. Definitive rejection refreshes wallet/settings/banks for review; success invalidates affiliate/withdrawals/ledger and offers history/wallet navigation.
- Withdrawal history now shows snapshotted fee and net from API. Backend migration is required; see backend handoff. Admin API manages fee/minimum/maximum; no separate admin frontend was added.
- Validation: 413 tests passed, TypeScript and changed-file ESLint clean, web export passed. Browser synthetic fixtures: desktop, 393px no overflow, 50,000 gross - 5,000 fee = 45,000 net; bank choice honored in submitted body; add-bank form saves and masks account; simulated 500 retry uses identical key/body and succeeds. No real withdrawal or bank account created in application DB during UI verification.
