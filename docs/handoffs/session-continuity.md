# Session continuity

- Report: web session unexpectedly disappears after a few minutes. Confirmed code paths: access expiry was ignored until a 401; no foreground keepalive; a just-rotated refresh replay revoked the entire family. Production trigger is not directly observed; tests reproduce the false revocation and missing proactive refresh.
- API keeps server expiresAt in memory and refreshes within 60 seconds of expiry before requests. Root installs a 30-second lifecycle check only while ready/authenticated. Visible/focus/online and native AppState active trigger checks; hidden/background/offline pauses them. Fresh/anonymous checks perform no network request. Missing expiry metadata retains legacy 401 recovery.
- Refresh is single-flight and uses existing browser Web Lock. Session restore/refresh retries one 409 after 250 ms, rereading HttpOnly cookie/native SecureStore. Temporary errors retain user/cache and back off 30 seconds or server Retry-After. A real refresh 401 still clears the session once; identity changes abort old mutations. Generation guards reject queued refreshes after logout and responses from previous logins (including same-account relogin).
- Backend counterpart: just-rotated obsolete refresh tokens get 409 for five seconds while the family has a valid token; no credentials issued from old token. Older replay/logout/password-reset revocation remain enforced. Existing access 15 min / refresh 30 day settings unchanged. No schema/CORS/storage/dependency changes.
